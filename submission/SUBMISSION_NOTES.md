# NCBI SRA submission — what is prepared and what you must supply

Generated by `scripts/27_sra_metadata.py`. Everything derivable from the data is filled in;
everything only you can know is marked `<<REQUIRED: ...>>` and left blank on purpose. A wrong
collection date or country in a public archive is harder to fix than an empty field.

## Files

| File | Purpose |
|---|---|
| `bioproject.tsv` | study-level record; submit this first |
| `biosample_attributes.tsv` | 16 sample records; submit second |
| `sra_metadata.tsv` | 16 run records; submit last, after BioSample accessions come back |
| `fastq_md5.txt` | MD5 checksums for all 16 FASTQ files, for upload verification |

## Order of operations

1. **BioProject** at https://submit.ncbi.nlm.nih.gov/ → returns a `PRJNA` accession.
2. **BioSample** using `biosample_attributes.tsv` → returns 16 `SAMN` accessions.
3. Paste those `SAMN` accessions into the `biosample_accession` column of `sra_metadata.tsv`.
4. **SRA** — upload the 16 `.fastq.gz` files (Aspera or FTP) and submit `sra_metadata.tsv`.

## BioSample package

The attribute columns provided match NCBI's generic **Microbe** package, which is what most
fungal culture submissions use in practice. NCBI may instead steer you to **MIGS: eukaryote**
(the package used for the published *P. ostreatus* genome BioSamples, e.g. SAMN15594696).
Confirm the package in the submission wizard before pasting — if it asks for MIGS.eu you will
additionally need `num_replicons`, `ploidy`, `propagation` and `assembly_quality`, none of
which are meaningful for a transcriptome and can be given as `not applicable`.

## Fields you must supply (56 in total across the 16 samples)

| Field | Why it cannot be auto-filled |
|---|---|
| `collection_date` | date of tissue harvest — not recorded anywhere in the data |
| `geo_loc_name` | country[:region] where cultures were grown, e.g. `USA:Indiana` |
| `biomaterial_provider` | supplier or source of the Harbor Blue P01 culture |
| `dev_stage` (Exudophore, Nodule) | your call — "vegetative mycelium" was auto-filled only for the two mycelium tissues |
| `grant_information` | funder and grant number |
| `release_date` | hold until publication, or release immediately |

## Points worth checking before you submit

- **`library_selection` is set to `PolyA`.** That describes the intended chemistry. Given that
  these libraries turned out to be 20–70% rRNA, poly(A) selection evidently underperformed,
  but `PolyA` remains the correct description of the protocol used and should not be changed
  to `RANDOM`.
- **`library_strategy` is `RNA-Seq`.** SRA has no dedicated term for 3'-end tag counting, so
  `RNA-Seq` is correct and the distinction is carried in `design_description`. This matters
  for reuse: anyone computing TPM from these data would be making an error, and the design
  description is the only place that warns them.
- **The UMI is inside the read name**, after an underscore, and is *not* a separate index read.
  This is stated in `design_description` because it is not recoverable from the FASTQ alone.
- **`tissue` values use your terminology**, including *exudophore*. There is no controlled
  vocabulary term for a newly described structure; the `description` column carries a short
  gloss so the record is interpretable without the paper.
- **Raw, untrimmed FASTQ files should be submitted** (`../GPNJ7M_fastq/*.fastq.gz`), not the
  trimmed versions in `qc/fastp/`. SRA expects reads as they came off the instrument.
